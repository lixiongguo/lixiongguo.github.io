田间杂草种类多，光照、土壤和生长阶段变化大，仅靠出厂模型难以长期维持检测的准确性，因此必须建立“边缘采数、云端更新、板端生效”的闭环。新草种只需用户提供少量样例并确认类别；模型更新无需算法人员驻场调参，转变为用户上传几张新草种图样即可触发的自助服务，体现边缘采集推理、云端训练演进的分工，使现场的准与快能随作物季持续保持。

### 智能大模型(SAM3)标注

**SAM3 简介。** SAM3（Segment Anything Model 3）是 Meta 推出的通用图像分割大模型，核心能力是**用自然语言直接指定要分割的对象**：只需给出一个类别词，模型就输出该类别的全部实例掩码，既不必为新目标重新训练，也不必逐点、逐框给提示。相较只支持点 / 框提示的前代模型，它把「文本 → 掩码」的开放词汇分割做进了网络结构，同一套权重即可泛化到训练中未见过的类别；本项目正是借助这一能力，用公共词 `plant` 一次性取到植株轮廓，把人工描边简化为轮廓修正。

本项目使用的权重取自官方发布的 SAM3（`facebook/sam3`），经 ModelScope 镜像下载后存放于工程内的模型目录，由标注脚本直接加载：主权重约 3.2 GB，另附一个不足 1 MB 的 BPE 词表用于文本提示编码。权重首次下载后长期驻留本地，日常标注不再联网，也不需要额外的服务端。

1. 在左侧选好数据源（如巡视导出的 `raw_img` + `label`）。  
2. 点击 **SAM3 标注**：  
   - 第一步：以公共提示词 `plant` 分割植物轮廓（不区分杂草与作物）；  
   - 第二步：用 **小分类器**（原型或 MobileNet 粗分类）为每个实例预写类别；置信不足时继承巡视导出的先验类别。  
3. 左侧可调节小分类器 **置信度阈值**（如 0.60）：宁可少自动标，也不要把错误伪标签直接当训练真值。  
4. 需要批量处理未标图时，点击 **自动标注剩余**。  



### 后处理SDF合并（碎块归为整株）

星状 / 发散杂草被自动分割拆碎时，碎块之间常有一到几像素的细窄空隙，这里借用图形学中的SDF**有符号距离场**（Signed Distance Field）进行合并处理。

对二值区域中每个像素，赋值为其到区域边界的最短欧氏距离，约定「区域外为正、区域内为负」。本工具只关心碎块之间的「外侧间隙」，实际只计算**外部欧氏距离场**——区域内像素置 0，区域外像素保留到最近边界的距离，省去内部距离与符号判定，计算量与严格的带符号版相比可省近一半。

**桥接的判定与计算。** 使用时取待合并实例的并集，对该并集的背景做欧氏距离变换，得到每个背景像素到最近前景的距离；把距离不超过阈值（默认 `20 px`）的背景像素填为前景，缝隙便沿其自然形状「长」成一片。阈值对缝隙两侧同时生效，故能被连通的缝隙宽度约为阈值的两倍，界面上即按「缝隙宽度的一半」提示该参数。

与形态学闭运算相比，闭运算用固定形状的核做腐蚀—膨胀，桥接宽度被核尺寸锁死、还容易把轮廓撑出棱角；SDF 的桥接宽度由真实缝隙厚度决定，连接处更贴合叶片走势。若缝隙过宽、填充后仍非单一连通块，则再退回等半径椭圆核的闭运算兜底，保证输出仍是一个实例。全局合并走两两判距 + 并查集分组，且默认**仅同类合并**，避免把杂草与相邻作物连成一株。

### 人工修正

自动标注只做粗轮廓，在叶片粘连、遮挡与错分类处会失真，伪标签若直接进训练集便越训越偏，故须人工修正后入库。
工具参考 LabelMe：左键逐点勾边、右键闭合（可撤销顶点，少于 3 点不能闭合），单击 / Ctrl 多选 / 框选可编辑实例，右键改类别，删除键移除误标，碎块用 SDF 合并归整，改动即时写回标签文件。
修正判据：边界贴可见叶缘、不挖空内部叶隙，一株一实例、粘连宁可拆开，遮挡按可见部分勾，类别按语义定且作物一律不可打入。

### 数据增强

针对样例少的问题，平台对图样做实例扩展和旋转、色彩、光照增强，同时混入历史数据回放训练，避免新类别挤占旧能力；新类别只追加编号，不改动已有编号，保证板端打击配置不受影响。训练以当前部署模型为起点微调而非从头训练，结束后自动评估，达标才入库；板卡联网拉取新版本，旧版本保留以便回滚。



### 训练参数

| 参数 | 典型设置 | 说明 |
|------|----------|------|
| 模型 | `yolo11n-seg.pt` | 轻量实例分割，适合车载边缘部署 |
| 实验名 | 如 `weed_crop_seg` | 权重输出目录名 |
| Epochs | 200 | 遍历全量数据的轮数，配合早停实际常在更少的轮次收敛 |
| Batch | 8 | 每步送入的样本数，显存不足时下调 |
| 图像尺寸 | 640 | 与板端推理输入保持一致，避免训练与部署的尺度错配 |
| 优化器 | `auto`（默认取 **AdamW**） | 由框架按迭代量与类别数自动决定：迭代数不超过 1 万时用 AdamW，超过则改用动量增强的 SGD 变体 |
| 初始学习率 | 约 `1.4e-3` | `auto` 下按类别数拟合（三类约 `0.00143`），不是固定的 `0.01` |
| 学习率策略 | 线性衰减至初值的 `1%` | 未启用余弦调度；衰减因子 `lrf=0.01`，即末轮学习率为初值的百分之一 |
| 动量 / 权重衰减 | `0.9` / `0.0005` | AdamW 的一阶矩系数与 L2 正则，权重衰减按批大小与累积步数归一化缩放 |
| 预热 | 3 个 epoch | 学习率由 0 线性升至设定值、动量由 `0.8` 升至 `0.9`，抑制训练初期的梯度震荡 |
| 早停 | 50 | 验证集指标连续 50 轮无提升即终止，节省算力并抑制过拟合 |

点击 **开始训练**，右侧查看进度与训练日志。完成后在「历史实验」中选择对应 run，使用生成的 `best.pt`；



## 模型下发与板端部署

- **运行环境**：RK3588 开发板（aarch64 Linux），相机与屏幕直连板卡。取图依赖**海康 MVS Linux SDK**（aarch64 版）：它提供相机枚举、连接、参数配置与原始图像抓取的完整接口，程序按配置文件的曝光、增益等参数连续取帧，无需自行实现相机通信协议；推理依赖 `rknn-toolkit-lite2`，图像处理与叠加绘制依赖 OpenCV。
- **模型转换**：训练框架产出的模型（ONNX / PyTorch / TensorFlow）不能直接被 NPU 执行，须先用**瑞芯微 RKNN-Toolkit2** 离线转换。该工具链是 NPU 的官方配套软件，负责模型加载与图优化（算子融合、常量折叠、无用节点裁剪）、指定目标平台、量化标定，以及与板端一致的模拟推理与精度分析，最终输出 `.rknn` 模型；它只提供 x86 Linux 版本，故在 WSL / Ubuntu 22.04 中运行。转换时以田间图像作为量化校准集做 INT8 量化以换取速度，但量化误差会损伤精度，本项目在 INT8 下分类头输出异常，因此最终采用 **FP16** 量化并确认三类输出正常。真正跑在板卡上的是轻量运行时 `rknn-toolkit-lite2`，它只做加载与推理，不含转换能力。
- **板卡直接推流**：相机画面在板端就地送往屏幕，不再经 PC 回传。板卡运行 **Wayland** 显示协议，由 **Weston 合成器**统一管理屏幕；程序不直接抢占显示控制器，而是把每帧图像压缩后写入一条 **GStreamer** 管道，管道负责解码、缩放，并通过 `waylandsink` 元素把画面作为 Wayland 表面交给 Weston 全屏合成，因而能与桌面共存而不打断 Weston。运行前还需把 `WAYLAND_DISPLAY` 与 `XDG_RUNTIME_DIR` 指向板端已有的 Wayland 会话，否则后台进程找不到套接字、画面无处可出。程序启动时自动探测板端可用的显示通道：存在 Weston 套接字且 GStreamer 可用时优先走上述 `waylandsink` 直出；其次在 X11 / Wayland 桌面下用 OpenCV 窗口；最后回退为直接写 `/dev/fb0` 帧缓冲。
