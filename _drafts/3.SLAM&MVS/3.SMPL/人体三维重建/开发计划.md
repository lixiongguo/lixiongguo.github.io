# 垂衣（Drape）系统开发计划

> 目标：给定一件已有衣物资产与任意目标体型/姿态，秒级输出贴合、无穿插、纹理正确的 3D 穿着效果，并提供可交互的浏览器演示。
> 版本：v0.1（计划稿）
> 周期：12 周（按每周 12–15 小时估算，可压缩到 8 周）

---

## 0. 项目卡片

| 项 | 内容 |
|---|---|
| 项目名 | 垂衣 / Drape |
| 一句话 | 一件衣服，穿到任意人身上 |
| 目标用户 | 虚拟试穿、数字人资产管线、独立开发者 |
| 核心主张 | 3D 资产级的衣物重定向（retargeting），不靠图像生成、不靠物理仿真 |
| 成功标准（三条同时满足） | ① 新环境 10 分钟内跑通 ② 单件 < 1s（CPU） ③ 相比 baseline 关键指标可量化提升 |
| 明确不做 | 不做 4D 动态捕获、不做物理仿真求解器、不做从零训练人体模型、不做 2D 图像试穿 |

**"不做"清单和"做"清单同等重要——它是控制范围的唯一手段。**

## 1. 背景与定位

### 1.1 现状

| 方向 | 代表工作 | 与本项目的关系 |
|---|---|---|
| 扫描捕获 | ClothCap | 需要专业设备，输出的是"某一件"衣物 |
| 合成数据生成 | Cloth3D / GCVAE | 提供训练数据与衣物表示参考 |
| 单图重建 | BCNet / MGN | 需要图像，输出的是"这一张图"的穿衣人体 |
| 版型编辑 | Design Preserve 等 | 关注编辑操作，不关注跨体型适配 |
| 2D 试穿 | 各类 GAN 方法 | 只出图像，无 3D 资产 |

### 1.2 缺口

**"已有 3D 衣物资产 → 任意体型"这一段是空的**。工业管线里靠美术手工在 Marvelous Designer 里重做，学术界只有零散工作。

### 1.3 本项目的边界

```
输入：衣物资产（OBJ + UV 纹理）+ 目标体型 β + 目标姿态 θ
输出：贴合后的衣物 mesh（SMPL 拓扑）+ 纹理 + 穿插报告
不做：从照片建人、布料物理、织物材质逆推
```

## 2. 技术方案

### 2.1 表示：SMPL + 位移（SMPL+D）

统一用 SMPL 拓扑承载衣物：

$$
P(\beta,\theta) = \mathrm{LBS}\bigl(\bar T + B_S(\beta) + D,\; J(\beta),\; \theta,\; W\bigr)
$$

- \(D\in\mathbb{R}^{N\times3}\)：在**规范姿态（rest pose）**下定义的顶点位移，\(N=6890\)（或细分到 14475）
- 蒙皮后再变到目标姿态，保证衣物随身体刚性运动

**选择理由**

| 优点 | 代价 |
|---|---|
| 拓扑统一，可用 GNN / 逐顶点回归 | 裙、连衣裙等拓扑差异大的品类需要改拓扑 |
| 与 SMPL 参数天然耦合，姿态迁移免费 | 贴身衣物的高频褶皱受限于拓扑密度 |
| 可直接复用 BCNet / Cloth3D 的偏移表示 | 无法表达飘逸层叠 |

> 报告里必须写清这个 trade-off，这是加分项而不是减分项。

### 2.2 七步管线

| 步 | 模块 | 输入 | 输出 | 关键技术 |
|---|---|---|---|---|
| ① | 规范化 | 衣物 OBJ | SMPL 拓扑的 \(D\) + 掩码 \(M\) | 非刚性 ICP、最近邻对应 |
| ② | 尺寸迁移 | 源 \(\beta_s\)、目标 \(\beta_t\)、\(D\) | 初始 \(D'\) | \(\Delta\beta\) 传播 + 迭代 Laplacian 平滑 |
| ③ | 保形精修 | \(D'\) | \(D''\) | ARAP / 拉普拉斯形变（抑制拉伸畸变） |
| ④ | 残差精修 | \(D''\)、\(\beta_t,\theta\) | \(D'''\) | **PCA 统计先验（零训练，默认）**；有 GPU 时才换 GNN |
| ⑤ | 碰撞处理 | \(D'''\)、身体 | 无穿插解 | 法线惩罚 \(\max(0,-o\cdot V_N)\) + 穿插投影 |
| ⑥ | 纹理迁移 | UV 图 | 重采样纹理 | UV 保持 + 屏幕空间重投影 |
| ⑦ | 导出渲染 | 最终 mesh | glTF | three.js 实时预览 |

**关键设计取舍**

- ④ 是 P1（可选）。没有它系统仍完整，只是质量差一档。
- ④ 默认**不训练模型**：对 Cloth3D 中提取的 \(D\) 做 SVD，取前 k 个主成分，推理时用 \((D\cdot\beta_t,\theta)\) 回归组合系数。整个计算在 CPU 上分钟级完成，**不需要 GPU、不需要 CUDA**。
- ⑤ 必须在 ②③ 之后做，否则早期穿插会被判断为"形变合理"。

### 2.3 纹理策略

- **保 UV**：衣物 UV 不动，只重采样到新边界
- **难点**：拉伸后同一 UV 面积对应更大物理面积，纹理会变糊
- **方案**：按面积比做各向异性重采样；报告里给出"纹理密度损失率"指标

### 2.4 渲染与演示

- glTF 2.0 导出（内嵌纹理）
- three.js + OrbitControls + 滑块（体型/姿态）
- 左右分屏对比：baseline（最近邻拉伸） vs 本方法

### 2.5 算力约束（CPU-first）

**没有 CUDA 环境不影响项目成立。** 逐模块算力需求：

| 步骤 | 算法 | 硬件需求 | 说明 |
|---|---|---|---|
| ① 配准 | 非刚性 ICP | **CPU 足够** | Open3D/libigl 的 ICP 均多线程，6890 顶点单次几十至几百 ms |
| ② 尺寸迁移 | \(\Delta\beta\) 传播 + Laplacian | **CPU 足够** | numpy + scipy.sparse，毫秒级 |
| ③ ARAP | 稀疏线性求解 | **CPU 足够** | 稀疏 Cholesky，单次迭代几十 ms |
| ④ 残差 | **PCA 统计先验** | **CPU 足够** | SVD 一次，分钟级；推理是矩阵乘法 |
| ④' 残差（可选） | GNN | GPU 更佳，CPU 勉强 | **唯一真正吃 GPU 的模块**，且属可裁剪范围 |
| ⑤ 碰撞 | BVH / trimesh | **CPU 足够** | 本身是串行几何查询 |
| ⑥ 纹理 | 面积比重采样 | **CPU 足够** | PIL + numpy |
| ⑦ 渲染 | three.js | 无需 CUDA | 在浏览器走 WebGL，集显即可 |

**结论**：P0 + P1 全链路 CPU 可跑通。GPU 只在想把 ④ 从 PCA 升级成 GNN 时需要。

**若确实要训练**（不推荐为它增加复杂度）：

1. 租卡按小时计费即可，不需要买机器——Cloth3D 上的残差网络从零训练约 10–30 小时，成本远低于折腾环境
2. 免费额度：Colab / Kaggle 的 T4 每周有配额，够跑消融
3. **不要**为了跑模型去配 CUDA 版 torch；CPU 版 `torch` 装上即可，配准与 ARAP 甚至不需要 torch

> 判断标准很简单：**只有"需要训练神经网络"才需要 GPU；本项目 90% 的工作量是几何算法，不是深度学习。**
> 这也是刻意选型的：把 GNN 放在 P2，正是为了让项目在没有算力时依然成立。

## 3. 数据

### 3.1 来源

| 类别 | 数量 | 用途 |
|---|---|---|
| Cloth3D 合成数据 | 按需抽取 2000–5000 帧 | PCA 先验（默认）/ 残差网络（可选）、压力测试 |
| SMPL 官方模板 + 自建衣物 | 20–30 件（T恤/衬衫/裤/裙/连衣裙） | 演示与评测 |
| 公开服装资产（免费授权） | 10–20 件 | 泛化测试 |

### 3.2 预处理

1. 非刚性 ICP 把衣物配准到 rest pose 的人体
2. 提取 body→garment 对应与衣物掩码
3. 裙/连衣裙：改拓扑（连通两腿 + 内侧 Laplacian 平滑），换用对应 Laplacian 矩阵
4. 统一坐标系与单位（米）

### 3.3 数据划分

**按衣物划分，不按帧划分**——同一件衣服不能同时出现在训练与测试，否则指标虚高。

## 4. 评测协议

### 4.1 指标

| 指标 | 定义 | 目标 |
|---|---|---|
| Chamfer | 双向最近点距离均值 (mm) | 越低越好 |
| 法线误差 | 对应面法线夹角均值 (rad) | 越低越好 |
| ARAP 能量 | \(\sum w_{ij}\|(p_i-p_j)-R_i(d_i-d_j)\|^2\) | 越低越"不拉伸" |
| 穿插率 | 位于人体内部的顶点占比 | < 1% |
| 自交面片 | 衣物自身相交的面片数 | 越低越好 |
| 围度误差 | 胸/腰/臀/衣长截面周长相对误差 | < 3% |
| 耗时 | 单件端到端 | **CPU < 1s 为硬指标**（GPU < 100ms 仅作记录，非目标） |

### 4.2 Baseline（必须有，否则数字没意义）

1. **直搬**：不做任何处理，直接套到目标体型
2. **均匀缩放**：按身高比例整体缩放
3. **最近邻拉伸**：SMPL 形状位移直接传播 + 无平滑

### 4.3 主观评测

10 人盲评，A/B 二选一（本方法 vs baseline 3），统计偏好率。**这是唯一能反映"看起来是否合理"的指标。**

## 5. 12 周计划

> 假设：单人、每周 12–15 小时。**不要求本地 GPU**——主线全程 CPU 可跑，训练类模块默认用零训练的统计先验替代（见 2.5）。

### 阶段一：跑通基线（W1–W2）

| 周 | 任务 | 产出 | 验收 |
|---|---|---|---|
| W1 | 环境搭建；SMPL 加载与参数化；定义 \(D\) 数据结构与坐标约定 | `smpl.py` + 单元测试 | 能渲染任意 β/θ 的人体 |
| W1 | 衣物 OBJ → SMPL 拓扑配准 | `register.py` | 20 件衣物全部配准成功 |
| W2 | Baseline 实现（直搬/缩放/最近邻） | `baselines.py` | 三种 baseline 均能出图 |
| W2 | 评测脚本 | `evaluate.py` + 指标表 | 自动生成本节 4.1 全部指标 |

**里程碑 M1**：三种 baseline 有完整指标表，作为后续所有改进的参照线。

### 阶段二：几何核心（W3–W6）

| 周 | 任务 | 产出 | 验收 |
|---|---|---|---|
| W3 | 尺寸迁移（\(\Delta\beta\) 传播 + Laplacian） | `transfer.py` | Chamfer 明显优于 baseline |
| W4 | ARAP 保形精修 | `arap.py` | ARAP 能量下降 > 30% |
| W5 | 碰撞检测与投影 | `collision.py` | 穿插率 < 1% |
| W6 | 裙/连衣裙拓扑适配 | `skirt_topo.py` | 裙类不再出现腿部穿模 |

**里程碑 M2**：核心几何管线完成，全品类可出结果，指标表更新。

### 阶段三：残差模块（W7–W8，可裁剪）

| 周 | 任务 | 产出 | 验收 |
|---|---|---|---|
| W7 | Cloth3D 数据管线 + **PCA 统计先验**（零训练，CPU） | `dataset.py` / `pca_residual.py` | 前 k 个主成分解释方差 > 90% |
| W8 | 残差精修 + 消融实验 | `residual.py` + 消融表 | 相比无残差有可量化提升 |
| W8（可选） | 有 GPU 时换 GNN，与 PCA 版本对比 | `gnn.py` / `train.py` | 训练可收敛且优于 PCA |

**W8 末只要没有可量化提升（无论 PCA 还是 GNN），整段砍掉，进入阶段四。**

### 阶段四：纹理与演示（W9–W11）

| 周 | 任务 | 产出 | 验收 |
|---|---|---|---|
| W9 | UV 保持 + 各向异性重采样 | `texture.py` | 纹理无明显拉伸糊化 |
| W10 | glTF 导出 + three.js 场景 | `demo/` | 浏览器可旋转缩放 |
| W11 | 交互：体型滑块、换衣、左右对比 | `demo/` | 单次切换 < 200ms |

### 阶段五：交付（W12）

| 任务 | 产出 |
|---|---|
| 技术报告（10–15 页） | 问题、方法、实验、取舍 |
| 演示视频（60–90s） | 从输入到结果的完整流程 |
| 开源整理 | README、一键脚本、Docker、权重 |

## 6. 优先级与降级

| 优先级 | 内容 | 缺失后果 |
|---|---|---|
| **P0 必须有** | ①配准 ②尺寸迁移 ③碰撞 ⑦导出渲染 + 评测表 | 缺任一，项目不成立 |
| **P1 应该有** | ARAP 精修、PCA 残差先验、纹理迁移、Web demo | 缺了质量与观感大幅下降 |
| **P2 可选** | GNN 残差、裙拓扑、自交处理 | 缺了影响覆盖面，不影响主张 |

**降级路径**：W8 末若进度落后，砍 P2，保 P0+P1。

## 7. 风险与应对

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| 配准失败（尤其裙） | 中 | 高 | 先用简单衣物验证管线，裙单独做拓扑 |
| 训练不收敛 | 中 | 中 | 直接用 P2P/GCN 经典结构，不做新设计；超时即放弃 |
| 无 GPU / 环境受限 | 高 | 中 | 主线 CPU-first（见 2.5）：配准/ARAP/碰撞/纹理全 CPU 实现；残差模块用 PCA 零训练替代 |
| 演示性能不足 | 中 | 中 | Web 端只做展示，计算放后端预生成 |
| 指标提升不明显 | 中 | 高 | 尽早建 baseline（W2 就完成），随时可判断 |
| 范围膨胀 | 高 | 高 | 严格执行"明确不做"清单 |
| 只做 demo 没有数字 | 中 | 高 | W2 必须先有评测脚本，不然后面无法证明 |

## 8. 工程规范

### 8.1 目录结构

```
drape/
├── drape/
│   ├── smpl.py          # 人体模型
│   ├── register.py      # 衣物配准
│   ├── transfer.py      # 尺寸迁移
│   ├── arap.py          # 保形形变
│   ├── collision.py     # 碰撞处理
│   ├── texture.py       # 纹理重采样
│   └── io.py            # OBJ/glTF
├── scripts/
│   ├── run_pipeline.py  # 一键：衣物 → 结果
│   └── evaluate.py      # 一键：跑全部指标
├── demo/                # three.js
├── data/                # 不入库，用脚本下载
├── weights/
└── docs/
```

### 8.2 环境

- conda + `environment.yml`，另提供 `Dockerfile`
- **CPU-only 可跑**：`requirements.txt` 不锁 CUDA 版 torch，无显卡机器 `pip install` 直接成功
- 可选加速都来自多线程而非 CUDA：`open3d` 的 ICP、`scipy.sparse` 的 ARAP 求解
- 固定随机种子；所有实验可复现

### 8.3 一键命令（README 必须只有这两行）

```bash
pip install -r requirements.txt
python scripts/run_pipeline.py --garment assets/tshirt.obj --beta 1.5 --theta 0
```
