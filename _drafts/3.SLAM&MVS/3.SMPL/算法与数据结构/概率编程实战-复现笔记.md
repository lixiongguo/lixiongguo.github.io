## 2. 元素 API 速查

### 2.1 原子元素

| 元素 | 签名 | 值类型 |
|---|---|---|
| `Flip(p)` | p 为 Double 或 Element[Double] | Boolean |
| `Select(w1 -> v1, w2 -> v2, ...)` | 权重自动归一化 | 值类型 |
| `Binomial(n, p)` | n 次独立试验成功数 | Int |
| `Normal(mu, sigma)` | 均值、标准差（可为元素） | Double |
| `Beta(a, b)` | α、β（可为元素） | Double |
| `Uniform(lo, hi)` | 区间 | Double |
| `Constant(v)` | 确定值 | v 的类型 |

要点：

- `Select` 的权重不必和为 1，Figaro 自动归一化；
- **离散 ≠ 有限**：整数无穷多，但仍是离散；
- 连续元素可直接当参数，实现"参数本身随机"：

```scala
val tempMean     = Normal(40, 9)
val tempVariance = Select(0.5 -> 80.0, 0.5 -> 105.0)
val temperature  = Normal(tempMean, tempVariance)
```

### 2.2 复合元素

| 元素 | 语义 | 用途 |
|---|---|---|
| `If(cond, thenE, elseE)` | 条件选择 | 分支 |
| `Dist(w1 -> e1, ...)` | 按权重选一个**元素** | 混合模型 |
| `Apply(e1, ..., f)` | 函数返回**值** | 派生量 |
| `Chain(parent, f)` | 函数返回**元素** | 有向依赖 |
| `^^(a, b, ...)` | 元组（≤5 个，可嵌套） | 联合查询 |
| `Inject(es: _*)` | 把集合注入成一个元素 | 未知数量 |
| `Container(es: _*)` | 动态下标访问 | 开放宇宙 |
| `FoldLeft / FoldRight / Reduce` | 自动分解的大函数 | 性能优化 |

### 2.3 元素命名的两种作用

```scala
// ① 只是标签（调试/日志用）
val x = Flip(0.3)("x")

// ② 绑定到宇宙（动态建模必需）
import com.cra.figaro.language.Universe
val u = Universe.createNew()
val waiting = Constant(0)("waiting", u)     // 必须命名才能跨步访问
```

**规则**：动态系统/粒子滤波中，**所有需要跨时间步访问的元素都必须命名并绑定宇宙**。

### 2.4 最容易踩的坑：两个 `Select(...)` 是不是同一个元素

| 情形 | 是否同一元素 | 原因 |
|---|---|---|
| 同一个 `val` 在代码里出现多次 | **是** | 指向同一实例 |
| 两处写了相同的构造函数 | **否** | 每次构造都创建新实例，可独立取值 |

```scala
val sunnyToday = Flip(0.2)
// 下面两处虽写法相同，却是两个互不相关的元素
val a = Select(0.6 -> "Hello, world!", 0.4 -> "Howdy, universe!")
val b = Select(0.6 -> "Hello, world!", 0.4 -> "Howdy, universe!")
```

类比 `new Greeting()`：两行 `new` 就是两个对象；而 `val y = x` 只是别名。

**这条规则解释了"为什么天气元素在多个复合元素里出现却共享取值"**——因为它们引用的是同一个 `val`。

## 3. Apply 与 Chain 的使用模板

### 3.1 Apply：函数返回"值"

```scala
// 单参数
val monthQuality = Apply(sunnyDaysInMonth, getQuality)

// 多参数（≤5）
val total = Apply(sales(0), sales(1), (a: Int, b: Int) => a + b)

// 常见用途：单位换算、取整、结构体取字段
val isHigh = Apply(temperature, (t: Double) => t > 30)
```

类型规则：

```
Apply : Element[T1] × ... × Element[Tn] × (T1,...,Tn => U) => Element[U]
```

### 3.2 Chain：函数返回"元素"

```scala
val goodMood = Chain(monthQuality, (s: String) =>
  if (s == "good")    Flip(0.9)
  else if (s == "average") Flip(0.6)
  else                Flip(0.1))
```

类型链条：

```
parent : Element[T]
f      : T => Element[U]
result : Element[U]
```

语义三步：**生成父值 → 用父值选出结果元素 → 从结果元素生成子值**。

> **一句话区分**：`Apply` 的函数返回**值**，`Chain` 的函数返回**元素**。要表达"父变量决定子变量的分布"，只能用 `Chain`。

### 3.3 CPD 表：手工写条件分布

```scala
val adequateToner = CPD(state,
  (off, _)         -> Flip(0.01),
  (on,  adequateColor) -> Flip(0.95),
  (on, !adequateColor) -> Flip(0.4)
)((s: PrinterState, t: Boolean) => (s, t))
```

`CPD` 适合枚举型依赖；参数一多就改用 `Chain`。

### 3.4 参数上限与分解

```scala
// ✗ 4 参数：11^4 = 14641 行
val total = Apply(b1, b2, b3, b4,
  (x1: Int, x2: Int, x3: Int, x4: Int) => x1 + x2 + x3 + x4)

// ✓ 拆成两两相加：121 + 121 + 441 = 683 行
val s12 = Apply(b1, b2, (x: Int, y: Int) => x + y)
val s34 = Apply(b3, b4, (x: Int, y: Int) => x + y)
val total = Apply(s12, s34, (x: Int, y: Int) => x + y)

// ✓ 更好的写法：自动分解
val total = FoldLeft(0, (x: Int, y: Int) => x + y)(bs: _*)
```

**这是 Figaro 里最基本的性能优化，应该成为默认习惯。**

## 4. 三类证据的 API

| 操作 | API | 可撤销 |
|---|---|---|
| 观测值（硬） | `e.observe(v)` | `e.unobserve()` |
| 条件（硬，谓词） | `e.setCondition(p => ...)` | 重新 `setCondition` 覆盖 |
| 约束（软，势） | `e.addConstraint(v => ...)` | 重新设置覆盖 |

等价关系（务必记住）：

```scala
y.observe(false)
// 完全等价于
y.addConstraint((b: Boolean) => if (b) 0.0 else 1.0)
```

**何时用哪种**：

- 有精确读数 → `observe`
- 有"必须满足"的集合约束 → `setCondition`
- 有"偏好/权重/不精确"信息 → `addConstraint`（**MH 场景优先用这个**）

## 5. 推理算法的调用

### 5.1 变量消除（精确）

```scala
// 静态快捷方式
VariableElimination.probability(elem, value)

// 实例方式（多目标/复用）
val alg = VariableElimination(elem1, elem2)
alg.start()
println(alg.probability(elem1, true))
alg.kill()
```

**注意**：VE 是精确的，所以同一模型多次运行结果**完全一致**——这是判断"是不是 VE"的最好标志。

### 5.2 重要性抽样

```scala
Importance.probability(elem, value)          // 默认样本数

val alg = Importance(100000, elem)           // 指定样本数
alg.start()
val p = alg.probability(elem, true)
alg.kill()
```

结果**每次运行都不同**，波动量级 ≈ ±1/√N。

### 5.3 Metropolis-Hastings

```scala
val alg = MetropolisHastings(
  numSamples = 100000,                 // 总样本数
  proposalScheme = ProposalScheme.default,
  burnIn = 1000,                       // 老化：丢弃开头样本
  interval = 10,                       // 间隔：每 10 步取 1 个
  elem1, elem2                         // 目标元素
)
alg.start()
println(alg.probability(elem1, true))
alg.kill()
```

**自定义提议**（解决"必须同时改两个变量"的死锁）：

```scala
val scheme = ProposalScheme(
  (universe, elem1, elem2) => ...,     // 一次同时改两个元素
  ...
)
```

**经验参数起点**（仅供起步，需按模型调）：

- `burnIn`：5000–10000（模型复杂就加）
- `interval`：5–20（样本相关性强就加大）
- `numSamples`：先跑 1 万看曲线，再决定是否加到 10 万

### 5.4 MPE（最可能解释）

```scala
// 小模型：精确
val alg = MPEVariableElimination()
alg.start()
println(alg.mostLikelyValue(elem))

// 大模型：BP 近似（指定迭代数）
val alg2 = MPEBeliefPropagation(10)

// 很大模型：MH + 模拟退火
val alg3 = MetropolisHastingsAnnealer(
  100000, ProposalScheme.default, Schedule.default(1.0))
```

### 5.5 粒子滤波

```scala
def nextUniverse(prev: Universe): Universe = {
  val next = Universe.createNew()
  val prevWaiting = prev.get[Int]("waiting")
  val prevSeated  = prev.get[List[Int]]("seated")
  // ... 用迁移函数生成新状态，并命名到 next
  Constant(newWaiting)("waiting", next)
  Constant(newSeated)("seated", next)
  next
}

val alg = ParticleFilter(initialUniverse, nextUniverse, 10000)
alg.start()

// 逐时间步推进，并注入证据
alg.advanceTime(List(NamedEvidence("waiting", Observation(2))))
println(alg.currentExpectation("seated", (l: List[Int]) => l.length))

alg.kill()
```

**关键点**：

- `nextUniverse` 必须**只依赖 prev**（纯函数），否则粒子会互相污染；
- 每个跨步元素都要 `get` / 命名；
- 粒子数 10000 是书中的量级，精度不够就加。

### 5.6 参数学习

```scala
val params = ModelParameters()

// 参数元素必须绑定 params 并命名
val spamProbability = Beta(2, 3)("spam probability", params)

class EmailModel(pc: ParameterCollection) {
  val isSpam = Flip(pc.get("spam probability"))
  // ...
}

// 学习：一份模型用 priorParameters
for (email <- trainingEmails) {
  val m = new EmailModel(params.priorParameters)
  // m.isSpam.observe(label)
}

val learningAlg = EMWithVE(10, params)   // 10 轮
learningAlg.start()

// 使用：换 posteriorParameters
val model = new EmailModel(params.posteriorParameters)
```

**EM 内核替换**（同一接口，不同代价/精度）：

| 算法 | 适用 |
|---|---|
| `EMWithVE(10, params)` | 小模型，精确 E 步 |
| `EMWithBP(10, params)` | 大但环少 |
| `EMWithIS(10, params)` | 中等规模 |
| `EMWithMH(10, params)` | 参数耦合强/硬约束多 |

### 5.7 完整应用骨架（垃圾邮件过滤，第 3 章）

书中唯一的端到端工程示范，架构固定为两块：

| 组件 | 职责 |
|---|---|
| **推理组件** | 给定邮件内容，判定是否垃圾邮件 |
| **学习组件** | 从标注数据估计参数（第 13 章） |

实现时的五个步骤（也是通用建模流程）：

1. **选元素**：是否垃圾邮件、各特征词是否出现、词数；
2. **定依赖**：词的出现依赖"是否垃圾邮件"；
3. **定函数形式**：布尔用 `Flip`，计数用 `Binomial`，概率参数用 `Beta`；
4. **设数值参数**：先用弱信息先验（如 `Beta(2,2)`）；
5. **用辅助知识**：如"垃圾邮件中异常词更多"。

关键设计（务必照做）：

```scala
class Model(pc: ParameterCollection) {
  val isSpam = Flip(pc.get("spam probability"))
  // ... 特征词、词数等
}

// 推理：用后验参数
val inferModel = new Model(params.posteriorParameters)
// 学习：用先验参数，逐样本 observe
```

**同一份模型类，两种参数集合**——这是"推理与学习共用模型"的标准做法，也是后面 EM 能直接复用的前提。

## 6. 可复现实验清单

每个实验给出：**目标 → 代码骨架 → 预期结果 → 验证点**。

### 实验 1：最简推理（第 2 章）

```scala
val sunnyToday = Flip(0.2)
VariableElimination.probability(sunnyToday, true)
```
**预期**：`0.2`
**验证**：多次运行结果完全一致（VE 的性质）。

### 实验 2：加入复合元素与证据（第 2 章）

```scala
val greetingToday = If(sunnyToday,
  Select(0.6 -> "Hello, world!", 0.4 -> "Howdy, universe!"),
  Select(0.2 -> "Hello, world!", 0.8 -> "Oh no, not again"))

VariableElimination.probability(sunnyToday, true)          // 0.2
greetingToday.observe("Hello, world!")
VariableElimination.probability(sunnyToday, true)          // 0.4286
```
**预期**：0.2 → 0.4285714285714285
**验证**：概率上升说明是"晴天时该问候语更常见"。

### 实验 3：向未来传播（第 2 章）

```scala
val sunnyTomorrow = If(sunnyToday, Flip(0.8), Flip(0.05))
// 同理构造 greetingTomorrow
VariableElimination.probability(greetingTomorrow, "Hello, world!")   // 0.28
greetingToday.observe("Hello, world!")
VariableElimination.probability(greetingTomorrow, "Hello, world!")   // 0.3486
```
**预期**：0.28 → 0.3485714285714286

### 实验 4：Apply 与 Chain（第 2 章）

```scala
// Apply
val monthQuality = Apply(sunnyDaysInMonth, getQuality)
// Chain
val goodMood = Chain(monthQuality, (s: String) =>
  if (s == "good") Flip(0.9) else if (s == "average") Flip(0.6) else Flip(0.1))
```
**验证点**：把 `Chain` 误写成 `Apply` 会**编译失败**（类型 `T => U` vs `T => Element[U]`）——这是最好的自查手段。

### 实验 5：MN 图像恢复（第 5 章）

```scala
val pixels = Array.fill(10, 10)(Flip(0.4))     // 100 个独立变量
val pair = ^^(pixel1, pixel2)
pair.addConstraint(bb => if (bb._1 == bb._2) 0.9 else 0.1)
```
**验证点**：`Array.fill` 每次调用都创建**新实例**；若要同一变量复用，必须用 `val` 保存引用。

### 实验 6：马尔科夫链控球（第 8 章）

```scala
val ourPossession: Array[Element[Boolean]] = Array.fill(90)(Constant(false))
ourPossession(0) = Flip(0.5)
for (minute <- 1 until 90)
  ourPossession(minute) = If(ourPossession(minute - 1), Flip(0.6), Flip(0.3))
```

**预期（书中的验收数字）**：

| 证据 | P(第 5 分钟控球) |
|---|---|
| 无 | 0.428745 |
| 观测第 4 分钟控球 | **0.6** |
| 再加第 3 分钟控球 | **0.6**（不变） |
| 加第 6 分钟控球 | **0.75** |
| 再加第 7 分钟控球 | **0.75**（不变） |

**验证点**："3 和 7 加了没用"就是马尔科夫假设生效的标志。若这两个数字变了，说明依赖写错了。

### 实验 7：硬币偏差的三种估计（第 9 章）

```scala
val bias = Beta(2, 5)
val numberOfHeads = Binomial(100, bias)
val toss101 = Flip(bias)

numberOfHeads.observe(63)
// 全贝叶斯
VariableElimination.probability(toss101, true)    // ≈ 0.6075
// MAP
val alg = MPEVariableElimination() 或 MPEBP       // ≈ 0.6095
// MLE：改用 Beta(1,1)
```
**预期**：0.6075 / 0.6095 / 0.63
**验证点**：三者顺序为 MLE > MAP > 全贝叶斯（本例中），先验把估计拉向 0.5。

### 实验 8：奥斯卡死锁与修复（第 11 章）

模型：200 演员、100 电影、300 出演；约束"恰好一次出演获奖"。

```scala
allAwards.setCondition(awards => awards.count(b => b) == 1)
```

**观察**：默认 MH 拒绝率 100%，链不移动。
**诊断**：任何单变量改动都会让获奖数为 0 或 2。
**修复 A**：自定义提议，一次同时改两个元素。
**修复 B**：把 `setCondition` 换成 `addConstraint`，允许违规状态（加权）。

**验收**：修复后 `alg.probability(actorAward, true)` 能给出非零且稳定的估计。

### 实验 9：粒子滤波（第 13 章）

状态：`waiting ∈ 0..6`、`seated` 为已入座时刻列表；
观测：每小时统计等待人数。
粒子数：**10000**。
**验收**：`currentExpectation("seated", l => l.length)` 随观测变化，且不同随机种子结果接近。

## 7. 性能调优清单

| 症状 | 原因 | 处理 |
|---|---|---|
| VE 极慢/内存爆 | 最大团太大 | 减少变量数；简化网络；改用 BP |
| 单个 `Apply` 卡死 | 参数过多导致因子爆炸 | 拆成 2 参数；用 `FoldLeft` |
| 对象建模后更慢 | 接口暴露太多变量 | 减小接口；把细节设为 `private` |
| 重要性抽样结果不稳 | 证据罕见 → 权重退化 | 加样本数；改 MH；软化约束 |
| MH 几乎不接受提议 | 硬条件 + 单变量提议 | 自定义提议；改软约束 |
| MH 结果漂移 | 未充分老化/间隔太小 | 加 `burnIn`、加 `interval` |
| 粒子滤波塌缩 | 粒子太少/重采样过频 | 加粒子数；检查迁移函数是否为纯函数 |
| EM 每轮很慢 | E 步用了重算法 | 换 `EMWithIS` / `EMWithMH` |

**三条硬经验**：

1. **先 VE 验证正确性**（小规模下），再换抽样跑大规模；
2. **任何 `Apply`/`Chain` 超过 2 个参数都要警惕**；
3. **抽样前先看证据概率**——太低就注定权重退化。

## 8. 排错手册

| 现象 | 最可能原因 | 定位方法 |
|---|---|---|
| 概率恒为 0 | 证据自相矛盾 | 去掉证据看先验；逐个加回 |
| 概率 = 1 | 约束权重写成常数 | 检查 `addConstraint` 返回值 |
| VE 结果与重要性抽样差很多 | 抽样样本不足 / 权重退化 | 加样本数看是否收敛 |
| 两次 `Select` 行为"不一致" | 以为是同一元素，实为两个实例 | 用 `val` 绑定后复用 |
| 动态模型报"找不到元素" | 未命名或未绑定宇宙 | 加 `("name", universe)` |
| 粒子滤波结果不动 | `nextUniverse` 依赖了外部可变状态 | 确保是 prev 的纯函数 |
| 学习后参数没变 | 用了 `priorParameters` 读取 | 改用 `posteriorParameters` |
| `Chain` 编译报类型错 | 函数返回了值而非元素 | 包一层 `Constant(...)` 或换 `Apply` |
