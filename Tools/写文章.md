## 文章Pipeline

思想：智能就是压缩，将书读薄

1.图摘:找关键点

2.图转文:翻译

3.文改写:AI加法+人工减法

4.公式编号与配图(合理截图)

5.代码跑通+代码融合

6.思考创新点

7.预出版：发公众号初步展示

## 自动化过程

原则：**判断归人，规则归脚本，编排归 Skill，复用归 MCP**。不为了自动化而自动化。

### 1. 七步分两类

| 步骤 | 性质 | 自动化程度 | 执行者 |
|---|---|---|---|
| 1 图摘 | 判断 + 多模态 | 高（只出初稿） | 模型 + 人工删减 |
| 2 图转文 | 生成 | 很高 | 模型 |
| 3 文改写 | 人机协作 | 中（只做加法） | AI 加、人减 |
| 4 公式配图 | 规则 + 审美 | 检查全自动、截图人工 | 脚本 + 人 |
| 5 代码跑通 | 确定性 | 很高 | 脚本 |
| 6 创新点 | 纯判断 | 低（只给提问） | 人 |
| 7 预出版 | 流程 | 很高 | 脚本 |

第 3、6 步是人的工作，全自动化会与「AI 加法 + 人工减法」的设计相悖。

### 2. 三层分工

| 层 | 管什么 | 不适合管什么 |
|---|---|---|
| Skill | 流程、检查点、何时停下来问人 | 确定性计算、批量调度 |
| 脚本 | 第 4/5/7 步：检查、执行、发布 | 判断内容好坏 |
| MCP | 把脚本暴露成工具，跨客户端/远程复用 | 决定调用顺序 |
| LangChain / LangGraph | 批量、无人值守、可评测 | 单篇写作（改流程要改代码） |

LangChain 只在同时满足两条时启用：要批量、要无人值守、要可复现对比。

### 3. 目录结构

```
Tools/skills/write-article/
├── SKILL.md                  # 七步流程与检查点
├── scripts/
│   ├── keypoints.py          # 图摘：要点 + 图号 + 页码
│   ├── article_lint.py       # 公式编号、图片引用、标题层级、frontmatter
│   ├── run_code.py           # 抽代码块执行并与文中输出比对
│   └── publish.py            # 生成 frontmatter/slug，串联 packpdf
└── references/
    ├── style.md              # 写作规范
    └── checklist.md          # 发布前检查清单
```

已具备、可直接复用：`Tools/skills/pack-pdf/`（公式检查、本地/OSS 图片、xelatex 打包、MCP server）。

### 4. 落地顺序：先牙齿，后流程

1. `article_lint.py`：把「文章质量」变成可判定的数字（编号断没断、图缺没缺、标题跳没跳级）。
2. `SKILL.md`：描述七步、每步产物、何时停下等人。
3. `publish.py`：串联 `packpdf check → images → build`。
4. MCP：只暴露原子动作（lint / run_code / publish / packpdf_*），不暴露「写文章」这种大步骤。
5. 批量初稿（可选）：30 篇以上、需断点续跑与成本统计时，再用 LangGraph 做状态机，并保留人工中断点。

没有脚本的 Skill 只是一段建议，模型可能跳过；脚本能独立跑，才是可复用的基础。

### 5. 暂不做

- 第 3 步全自动改写（丢掉人工减法，风格会漂移）。
- 第 6 步让模型代写创新点（结论必须由作者给出）。
- 为每一步都做一个 MCP 工具（工具颗粒度太细，模型编排反而更乱）。
