# 渲染错误排查记录：代码块字符丢失与中文错位

- 日期：2026-11-08
- 对象：`PDF_output/参数化算法.pdf`（237 页，26 MB）
- 来源：`_posts/1.Parameterization`（6 章 33 篇成稿）
- 结论：**不是字体缺失，是代码块缺字形被 LaTeX 静默丢弃**

## 一、现象

打包出来的 PDF 里，代码块有两类不正常：

1. 代码里写了 `π`，打印出来是空的

   ```cpp
   // markdown 原文
   rot = Rotate2D(d2_2d, k * π / 2);

   // 修复前 PDF 渲染
   rot = Rotate2D(d2_2d, k * /2);
   ```

2. 代码块里的中文注释与等宽英文对不齐，缩进跳动

   ```cpp
   for (每条边 e) {
       if (e 是边界) continue;
       // 边界边保持 0
   ```

正文部分（宋体、中英混排）其实是正常的，问题只在 `\ttfamily` 环境。

## 三、根因

### 1. `π` 丢失：Latin Modern Mono 没有希腊字母

pandoc 默认模板里只传了 `mainfont` 和 `CJKmainfont`，代码块落到 `\ttfamily` → Latin Modern Mono。

LM Mono 只覆盖 Latin 和少量符号，**不含 Greek**。xelatex 遇到缺字形不会报错、也不会画豆腐块，直接跳过该字符。所以：

- 编译日志干净
- 字体检查全部嵌入
- 文本层里 `π` 其实还在（属于 CID 编码的空白），视觉上是空的

这类问题只能靠**看渲染图**发现。

### 2. 中文错位：没有 `\setCJKmonofont`

`build/merged.tex` 的导言区只有：

```latex
\usepackage{xeCJK}
\setCJKmainfont[]{Songti SC}
```

`\setCJKmonofont` 缺失时，`\ttfamily` 下的中文回退到 `\setCJKmainfont`（比例宋体）。汉字本身是全角等宽，但和 Menlo/LMMono 这类窄等宽西文混排时，宽度比不是整数倍，于是缩进一栏一栏地跳。

## 四、修复

改在 `packpdf/core.py` 的两个地方。`_fix_latex` 是 pandoc 出 tex 之后、xelatex 编译之前的文本修正钩子，本来就是干这类事的位置（已有的 `\textdollar` 修正、`\usepackage{float}` 注入都在这儿）。

### 1. 新增等宽字体选择

```python
def _mono_font() -> str:
    """代码块西文字体。

    不能用 Latin Modern Mono：它没有希腊字母，代码里的 π、α 等会被静默丢弃，
    `k * π / 2` 会渲染成 `k * /2`，语义直接坏掉。
    """
    font = os.environ.get('PACKPDF_MONO_FONT', '').strip()
    if font:
        return font
    if sys.platform == 'darwin':
        return 'Menlo'
    if sys.platform.startswith('linux'):
        return 'DejaVu Sans Mono'
    return 'Consolas'
```

### 2. 在 `_fix_latex` 里注入

```python
    if r'\setCJKmonofont' not in tex:
        cjk = _cjk_font()
        anchor = r'\setCJKmainfont[]{%s}' % cjk
        if anchor in tex:
            tex = tex.replace(
                anchor,
                anchor + '\n'
                + r'\setCJKmonofont[]{%s}' % cjk + '\n'
                + r'\setmonofont[]{%s}' % _mono_font(),
            )
```

注意用 `_cjk_font()` 动态拼锚点，而不是硬编码 `Songti SC` —— 用户可能通过 `PACKPDF_CJK_FONT` 换字体，硬编码会匹配不上而静默失效。

## 六、遗留

行内公式基线偏低：第 5 页 `$S \subset \mathbb{R}^3$` 比中文基线低 1–2 px。

属于 `unicode-math` 与 `\setmainfont` 的对齐问题，调 `\setmathfont` 的 Scale 会影响全书 207 个含公式页面的排版。收益不确定、回归风险大，暂时保留。

## 七、以后怎么查同类问题

```bash
# 1. 字体清单（谁在渲染）
python3 -c "
import fitz; doc=fitz.open('x.pdf')
for f in doc[0].get_fonts(full=True): print(f[1], f[3])"

# 2. 某字符是否真的进了 PDF
python3 -c "
import fitz; doc=fitz.open('x.pdf')
print(sum('π' in p.get_text() for p in doc), '页含 π')"

# 3. 视觉检查：一定要放大，低 dpi 看不出缺字符
```

判断口诀：

- 字体全部嵌入 + 文本层正常 + 渲染缺字 → **字体缺字形**，换 `monofont`
- 只有代码块中文错位 → **缺 `\setCJKmonofont`**
- 整页空白/豆腐块 → 字体完全不含 CJK，属于另一类问题
