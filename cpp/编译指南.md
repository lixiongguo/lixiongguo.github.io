## 1. 构建体系里各文件的分工

| 路径 | 角色 |
| --- | --- |
| `cpp/wasm_packages.yaml` | **清单 / 单一事实来源**：声明每个包的源文件组、导出符号、`make_target`、以及"哪个页面用哪些包" |
| `cpp/build_wasm.ps1` | Windows 包装脚本：按清单把包名解析成 `make_target`，**自动 source `cpp/emsdk/emsdk_env.ps1`**，再调用 `make`（或包目录下的 `build.ps1`，见 §5-Q1） |
| `cpp/build_wasm.sh` | 同上，bash 版本；用 `python3 + PyYAML` 解析清单 |
| `conformal-parameterization/wasm/Makefile` | 真正描述各包的源文件列表、`-I` 路径、链接参数的 Makefile |
| `Fluid3D/wasm/build.ps1` | **包级**构建脚本（Fluid3D 是独立子工程，有自己的 Makefile 和一个"没有 make 也能编"的 build.ps1） |
| `Tools/wasm_build_manager/app.py` | PyQt5 图形界面：可视化包/源文件/体积，并调用 `build_wasm.ps1`（Windows）或 `build_wasm.sh` 触发构建 |
| `assets/wasm/` | 所有 `.js` + `.wasm` 的落地产物目录（Jekyll 通过 `_config.yml` 的 `keep_files` 保留） |

## 2. 前置条件

### 2.1 Emscripten（必需）

本仓库**已内置** emsdk：

- `cpp/emsdk/` —— emsdk 本体
- `cpp/emsdk/upstream/emscripten/em++.bat`（Windows）/ `em++`（Linux/macOS）—— 已安装的工具链
- `cpp/emsdk/upstream/bin/*.exe` —— 已安装的 LLVM 二进制

正常情况**无需再install**。若编译时报找不到 `em++`，在 `cpp/emsdk` 下重新激活一次：

```powershell
cd cpp\emsdk
.\emsdk install latest      # 只在工具链缺失时才需要
.\emsdk activate latest
```

验证：

```powershell
em++ --version
```

> 注意：`source` 是 **Bash** 内置命令，在 PowerShell 里会报
> `无法将"source"项识别为 cmdlet`。PowerShell 的等价写法是点源 `. ./emsdk_env.ps1`。
> 但用 §3.1 的包装脚本时这两步都由脚本代劳，不用手写。

### 2.2 Eigen（必需）

头文件库已在 `cpp/deps/eigen-3.4.0`，Makefile 中通过

```make
EIGEN_PATH := ../../deps/eigen-3.4.0
```

引用，无需额外安装。它必须存在，否则会报 `Eigen/Dense not found`。

### 2.3 GNU make（可选）

Makefile 路线需要 `make`。Windows 上默认常常没有（Git Bash 也不自带 `make`），
此时请走 §3.1 的包装脚本 + §6 的**包级 `build.ps1`** 方案，或自行安装：

```powershell
choco install make -y        # 需要管理员权限
```

### 2.4 Python 环境（仅图形界面需要）

```powershell
pip install -r Tools/wasm_build_manager/requirements.txt   # PyQt5>=5.15, PyYAML>=6.0
```

## 5. 常见问题排查

### Q1：包装脚本报 `make: command not found`，或直接失败

**原因**：`build_wasm.ps1` 的逻辑是"没有 `make` 时，优先用**包目录下自己的 `build.ps1`**"：

```powershell
# cpp/build_wasm.ps1
$LocalBuildPs1 = Join-Path $ResolvedMakeDir "build.ps1"
$HasMake = [bool](Get-Command make -ErrorAction SilentlyContinue)

if ((Test-Path $LocalBuildPs1) -and -not $HasMake) {
    & $LocalBuildPs1            # ← 走这里就完全不需要 make
}
# 否则回退到: make -C <包目录> <make_target>
```

- `cpp/Fluid3D/wasm/build.ps1` —— **存在**，所以 Fluid3D 在没有 make 的机器上也能编
- `cpp/conformal-parameterization/wasm/build.ps1` —— **不存在**，于是回退到 `make` → 失败

**解决**（二选一）：

1. 安装 `make`（§2.3），然后照 §3 正常使用包装脚本；
2. 给 `cpp/conformal-parameterization/wasm/` 补一个不含 make 的 `build.ps1`
   —— 完整脚本见 **§6 附录 A**（与 Makefile 等价）。

### Q2：`make build-page-all` / `make build-dgp-compat` 报 `No rule to make target`

**原因**：Makefile 本身不完整，属于已知缺口：

- `.PHONY` 与 `build-all` / `build-page-all` 的依赖里列了
  `build-base-mesh`、`build-cutseam-mesh`、`build-solver`、`build-lscm`、`build-abf`、
  `build-arap`、`build-dgp-compat` —— 但**这些目标都没有对应规则**，因此 `make build-all`
  和 `make build-page-all` 必然失败；
- `build-bdhm` 的规则里用的是 `$(BD_DEFORM_COMPAT_INC)` / `$(BD_DEFORM_COMPAT_SRCS)`，
  而这两个变量**全文未定义**，并且它编译的是 `bindings_bd_deformation_compat.cpp`
  （看起来是把 bd_deformation 的规则复制过来忘了改）；`build-bd-deform-compat` 则完全没有规则；
- `build-field-compat`、`build-abel-compat` 各被定义了**两次**，make 会提示 recipe 被覆盖。

**当前可用的叶子目标**（有真实规则）只有：

```text
build-simple-compat   build-bd-lscm   build-field-compat   build-abel-compat   build-ruppert
```

**绕过办法**：不要用 `page` / `all` 聚合目标，直接逐个编需要的包；
或使用 §6 的 `build.ps1`（其中 `build-page-all` 只聚合"真正可用"的那几个包）。

### Q3：改了 C++ 源码，浏览器行为却没变

`.wasm` 是**预编译二进制**。改动 `.cpp` 后必须：

1. 重新编译该包（§3）；
2. 重启 `bundle exec jekyll server`；
3. 浏览器 **Ctrl+F5** 强制刷新 —— `.wasm` 极易被缓存，不硬刷等于白编。

### Q4：找不到 `em++`

- 确认 `cpp/emsdk/upstream/emscripten/em++.bat`（Windows）存在；
- 在 `cpp/emsdk` 下 `.\emsdk activate latest` 重新激活；
- 或直接跑包装脚本，它会自动 `. $RepoRoot\cpp\emsdk\emsdk_env.ps1`。

### Q5：编译成功，页面里 wasm 仍然 404 / 加载失败

- 确认产物在 `assets/wasm/`，且 `.js` 与 `.wasm` **同名成对**（两者都要部署）；
- `_config.yml` 里 `keep_files` 已包含 `assets/wasm/*.wasm` 与 `assets/wasm/*.js`，不要随意删改；
- 检查浏览器 Network 面板里的实际请求路径是否与页面里 `WasmLoader` 拼接的路径一致。

### Q6：只想重编一个包，避免全量

按 §4 的表格找到包名，直接 `.\build_wasm.ps1 -Target <包名>`。
多个页面共享的包（如 `uv_unwrap_simple`）只需编一次。

### Q7：在 PowerShell 里 `em++` 报 `Remove-Item : Cannot find 'Env:\_PYTHON_SYSCONFIGDATA_NAME'`

**现象**：环境变量已经设置成功（能看到 `EMSDK = ...`），但命令以 exit code 1 结束，
报错位置在 `cpp/emsdk/upstream/emscripten/em++.ps1:28`：

```text
[safe-delete][SAFE_DELETE_FAIL_CLOSED] {"target":"Env:\\_PYTHON_SYSCONFIGDATA_NAME", ...}
Remove-Item : Cannot find 'Env:\_PYTHON_SYSCONFIGDATA_NAME' because it does not exist.
```

**原因**：PowerShell 默认优先命中 `em++.ps1` 这个包装脚本，它内部有一句
`Remove-Item -ErrorAction Ignore Env:\_PYTHON_SYSCONFIGDATA_NAME`。当运行环境
（某些 IDE 终端 / PowerShell 配置）对删除类操作做了 fail-closed 拦截时，这句会直接抛异常。

**解决**：显式调用批次脚本，绕开 `.ps1` 包装：

```powershell
cd <repo>
. .\cpp\emsdk\emsdk_env.ps1
cd cpp\conformal-parameterization\wasm
& "$env:EMSDK\upstream\emscripten\em++.bat" -O3 -std=c++17 ... -o ../../../assets/wasm/uv_unwrap_simple.js ...
```

**编译完成后务必同步到 Jekyll 输出目录**（`_config.yml` 的 `destination` 是 `docs`）：

```powershell
Copy-Item assets\wasm\<包名>.js, assets\wasm\<包名>.wasm docs\assets\wasm\ -Force
```

再用浏览器 **Ctrl+F5** 强刷。

> 说明：`-O3` 构建下 Emscripten 会压缩 wasm 的导入/导出名（wasm 里不会出现
> `solve_lscm` 这样的字面量，而是 `"o"`）。这是正常的，胶水 JS 里的
> `assignWasmExports()` 保存了完整映射。**只要 `.js` 与 `.wasm` 来自同一次 em++ 调用就配套**，
> 判断方法是看两者时间戳是否一致。

## 6. 附录 A：`conformal-parameterization/wasm/build.ps1`（无 make 版）

当机器上没有 GNU make 时，把下面内容保存为
`cpp/conformal-parameterization/wasm/build.ps1` 即可让 §3.1 的包装脚本与
`Tools/wasm_build_manager` 正常工作（这是 `Fluid3D/wasm/build.ps1` 的同款思路，
参数与 `Makefile` 中的源文件组 / `-I` 路径 / 链接选项一一对应）。

```powershell
# ============================================================
#  conformal-parameterization WASM 构建（无需 GNU make）
#  等价于同目录 Makefile；用法：
#    .\build.ps1                         # 默认 = build-simple-compat
#    .\build.ps1 -Target build-simple-compat
#    .\build.ps1 -Target build-page-all
# ============================================================
param(
    [string]$Target = "build-simple-compat"
)

$ErrorActionPreference = "Stop"

$WasmDir  = Split-Path -Parent $MyInvocation.MyCommand.Path   # .../conformal-parameterization/wasm
$PkgRoot  = Split-Path -Parent $WasmDir                       # .../conformal-parameterization
$CppRoot  = Split-Path -Parent $PkgRoot                       # .../cpp
$RepoRoot = Split-Path -Parent $CppRoot                       # repo 根目录
$OutDir   = Join-Path $RepoRoot "assets\wasm"
$Eigen    = Join-Path $CppRoot  "deps\eigen-3.4.0"

$EmsdkEnv = Join-Path $CppRoot "emsdk\emsdk_env.ps1"
if (Test-Path $EmsdkEnv) { . $EmsdkEnv }
if (-not (Get-Command em++ -ErrorAction SilentlyContinue)) {
    throw "找不到 em++。请先在 cpp\emsdk 执行 .\emsdk activate latest"
}
New-Item -ItemType Directory -Force -Path $OutDir | Out-Null

function P([string]$rel) { Join-Path $PkgRoot $rel }
function H([string]$rel) { Join-Path $CppRoot $rel }

# ---------- 源文件组（对应 Makefile） ----------
$BASEMESH = @(
    "BaseMesh/Mesh.cpp","BaseMesh/MeshIO.cpp","BaseMesh/Vertex.cpp","BaseMesh/Edge.cpp",
    "BaseMesh/Face.cpp","BaseMesh/HalfEdge.cpp","BaseMesh/GaussianCurvature.cpp",
    "BaseMesh/QcError.cpp","Parameterization/Parameterization.cpp") | ForEach-Object { P $_ }

$SOLVER = @(
    "Solvers/Solver.cpp","Solvers/AugmentedLagrangian.cpp","Solvers/MixedIntegerProgram.cpp"
) | ForEach-Object { P $_ }

$LSCM = @(
    "Parameterization/SimpleParam/LSCM/Lscm.cpp",
    "Parameterization/SimpleParam/LSCM/Scp.cpp") | ForEach-Object { P $_ }

$CUTSEAM = @( (P "CutSeamMesh/CutSeamMesh.cpp") )

$CONE = @(
    "Parameterization/ConeParam/ConeParameterization.cpp",
    "Parameterization/ConeParam/Conformal/CirclePatterns.cpp",
    "Parameterization/ConeParam/Conformal/Cetm.cpp",
    "Parameterization/ConeParam/RicciFlow/RicciFlow.cpp") | ForEach-Object { P $_ }

# ---------- include 路径（对应 Makefile 的 *_INC） ----------
$IncBase   = @("-I$Eigen", "-I$(P 'BaseMesh')", "-I$(P 'Parameterization')")

$IncSimple = $IncBase + @(
    "-I$(P 'Parameterization/SimpleParam/LSCM')",
    "-I$(P 'Parameterization/SimpleParam/ABF')",
    "-I$(P 'Parameterization/SimpleParam/ARAP')",
    "-I$(H 'HGP/FastHGP')",
    "-I$(P 'CutSeamMesh')",
    "-I$(P 'Parameterization/ConeParam')",
    "-I$(P 'Parameterization/ConeParam/Conformal')",
    "-I$(P 'Parameterization/ConeParam/RicciFlow')",
    "-I$(P 'Parameterization/ConeParam/IncrementalFlattenning')",
    "-I$(P 'Solvers')","-I$(P 'Solvers/Mosek')")

$IncField  = $IncBase + @(
    "-I$(P 'CutSeamMesh')",
    "-I$(P 'Parameterization/GlobalFieldsParam')",
    "-I$(P 'Parameterization/CutSeamParam')",
    "-I$(P 'Parameterization/CutSeamParam/HoloOneForm')",
    "-I$(P 'Parameterization/SimpleParam/LSCM')",
    "-I$(P 'VectorFileds')",
    "-I$(P 'VectorFileds/PrincipalCurvatureFields')",
    "-I$(P 'Solvers')","-I$(P 'Solvers/Mosek')")

$IncAbel   = $IncBase + @(
    "-I$(P 'CutSeamMesh')",
    "-I$(P 'Parameterization/CutSeamParam')",
    "-I$(P 'Parameterization/CutSeamParam/Abel_Jacoi')",
    "-I$(P 'Parameterization/SimpleParam/LSCM')")

$IncBdLscm = $IncBase + @(
    "-I$(P 'Parameterization/SimpleParam/LSCM')",
    "-I$(P 'Bounded/bounded_distortion_mapping')")

# ---------- 链接参数（对应 EM_FLAGS / EM_FLAGS_COMPAT） ----------
$Common = @("-O3","-std=c++17","-Wall","-Wextra")

$Compat = @(
    "-s","MODULARIZE=1","-s","ALLOW_MEMORY_GROWTH=1","-s","WASM=1",
    "-sEXPORTED_FUNCTIONS=['_malloc','_free']",
    "-sEXPORTED_RUNTIME_METHODS=['ccall','cwrap','getValue','setValue']")

$Embind = @(
    "--bind","-s","MODULARIZE=1","-s","ALLOW_MEMORY_GROWTH=1","-s","WASM=1",
    "-s","FORCE_FILESYSTEM=1",
    "-sEXPORTED_RUNTIME_METHODS=['ccall','cwrap','getValue','setValue','FS']")

function Invoke-Build {
    param([string]$Name,[string]$OutJs,[string[]]$Sources,[string[]]$Includes,
          [string[]]$Flags,[string]$ExportName)
    Write-Host "[$Name] em++ -> $OutJs" -ForegroundColor Cyan
    & em++ @Common @Includes @Sources -o $OutJs @Flags "-s","EXPORT_NAME=$ExportName"
    if ($LASTEXITCODE -ne 0) { throw "[$Name] 编译失败 (exit $LASTEXITCODE)" }
    Write-Host "[$Name] OK" -ForegroundColor Green
}

function Build-Simple {
    Invoke-Build -Name "uv_unwrap_simple" -OutJs (Join-Path $OutDir "uv_unwrap_simple.js") `
        -Includes $IncSimple -Flags $Compat -ExportName "UvUnwrapSimpleSolver" -Sources (@(
            (P "wasm/bindings_uv_unwrap_simple_compat.cpp")) + $BASEMESH + $SOLVER + $LSCM + @(
            (P "Parameterization/SimpleParam/ABF/AbfPlusPlus.cpp"),
            (P "Parameterization/SimpleParam/ABF/LinAbf.cpp"),
            (P "Parameterization/SimpleParam/ARAP/ARAP.cpp"),
            (P "Parameterization/SimpleParam/ARAP/Tutte.cpp"),
            (H "HGP/FastHGP/FastHGPSimple.cpp"),
            (P "CutSeamMesh/CutSeamMesh.cpp"),
            (P "Parameterization/ConeParam/IncrementalFlattenning/IncrementalFlattening.cpp")) + $CONE)
}

function Build-Dgp {
    Invoke-Build -Name "dgp_basic" -OutJs (Join-Path $OutDir "dgp_basic.js") `
        -Includes $IncBase -Flags $Compat -ExportName "DgpBasicSolver" -Sources (@(
            (P "wasm/bindings_dgp_basic_compat.cpp")) + $BASEMESH)
}

function Build-Field {
    Invoke-Build -Name "uv_unwrap_field" -OutJs (Join-Path $OutDir "uv_unwrap_field.js") `
        -Includes $IncField -Flags $Compat -ExportName "UvUnwrapFieldSolver" -Sources (@(
            (P "wasm/bindings_uv_unwrap_field_compat.cpp")) + $BASEMESH + $CUTSEAM + $SOLVER + $LSCM + @(
            (P "Parameterization/GlobalFieldsParam/GlobalFieldsParameterization.cpp"),
            (P "Parameterization/GlobalFieldsParam/QuadCover.cpp"),
            (P "Parameterization/GlobalFieldsParam/MIQQuad.cpp"),
            (P "Parameterization/CutSeamParam/CutSeamParameterization.cpp"),
            (P "Parameterization/CutSeamParam/HoloOneForm/HolomorphicOneForm.cpp"),

function Build-Abel {

        -Includes $IncAbel -Flags $Compat -ExportName "UvUnwrapAbelJacobiSolver" -Sources (@(

        -Includes $IncBdLscm -Flags $Embind -ExportName "BD_LSCMModule" -Sources (@(
            (P "wasm/bindings_bd_lscm.cpp")) + $BASEMESH + $LSCM + @(

}

    Invoke-Build -Name "ruppert" -OutJs (Join-Path $OutDir "ruppert.js") `
        -Includes @() -Flags $Compat -ExportName "RuppertModule" -Sources @(
            (P "wasm/bindings_ruppert_compat.cpp"))
}

switch ($Target) {
    "build-simple-compat" { Build-Simple }
    "build-dgp-compat"    { Build-Dgp }
    "build-field-compat"  { Build-Field }
    "build-abel-compat"   { Build-Abel }

    "page"                { Build-Simple; Build-Dgp; Build-Field; Build-Abel; Build-BdLscm }

Write-Host "全部完成 → $OutDir" -ForegroundColor Green
```

>

>     } else {
>         & $LocalBuildPs1
>     }
>     if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
>     return
> }
> ```

## 7. 附录 B：新增一个包时需要同步的地方

1. 在 `cpp/conformal-parameterization/wasm/` 写 binding `.cpp`；
2. 在 `cpp/conformal-parameterization/wasm/Makefile` 增加 `build-xxx-xxx` 规则
   （源文件列表 + `-I` 路径 + `EM_FLAGS*` + `-s EXPORT_NAME=...`），并加入 `.PHONY`；
3. 在 `cpp/wasm_packages.yaml` 的 `packages:` 下登记
   `kind / export_name / make_target / binding / methods / exports / sources`；
4. 在 `pages:` 下把新包挂到使用它的页面上（`load: eager | lazy`）；
5. 若该目录没有 `build.ps1` 且本机没有 `make`，参考 §6 增设或扩展现有 `build.ps1`；
6. `Tools/wasm_build_manager` 无需改动 —— 它直接读 `wasm_packages.yaml` 渲染。
